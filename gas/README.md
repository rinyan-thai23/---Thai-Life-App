# タイ暮らし：GAS手動運用セット

サンプルアプリ：https://thai-life-companion.rinyan.chatgpt.site

## 最初に行うこと（自動化しません）
1. Googleスプレッドシートを新規作成します。
2. 「拡張機能 → Apps Script」を開きます。
3. Code.gsの内容を、エディタの「コード.gs」に貼り付けて保存します。
4. 関数一覧からsetupThaiLifeを選んで実行し、ご自身のGoogleアカウントで必要な権限を許可します。
5. スプレッドシートを開き直すと「タイ暮らし」メニューが出ます。
6. 「JSONを書き出す」を押し、daily.jsonをダウンロードします。
7. サンプルアプリ下部の「試作用データを読み込む」から、このファイルを選びます。
8. この端末だけで為替・数字・休日の反映を確認できます。ページを再読み込みすると公開済みデータに戻ります。

初期設定は既存シートの内容を上書きしません。最初は新規スプレッドシートで行ってください。

## シートの編集
### 為替
| key | value |
|---|---|
| thb_jpy | 1バーツあたりの円（例4.6） |
| usd_thb | 1ドルあたりのバーツ（例33） |
| is_sample | ダミーならTRUE、実際の参考レートならFALSE |
| as_of | 実データの日付をYYYY-MM-DDで入力 |

最初は手入力です。為替APIの取得は実装していません。実レートにする場合は出典を確認して日付を入力してください。

### ラッキーナンバー
number、is_sample、dateの3列です。数字は00〜99を1〜5個。先頭の0を保持します。is_sampleとdateは全行同じ値にします。本番にするならFALSEと当日の日付を入力します。
過去の宝くじデータから数字を作る処理はまだありません。「宝くじ履歴」は受け取り用の空シートです。データの列を確認してから分析処理を作ります。当選予測として扱いません。

### 休日
| 列 | 内容 |
|---|---|
| date | 西暦YYYY-MM-DD |
| name_ja / name_en | 日本語名・英語名 |
| type | bank（銀行）／government（官公庁）／public（祝日） |
| province | all、またはアプリの英語県名と一致する値（例Bangkok） |
| source | 確認した公式ページのhttps URL |
| checked_at | その情報を確認した日付 |

初期データは2026年のBOT銀行休業日20件（バンコク限定1件を含む）です。南部の宗教休日などは未収録です。2027年は公式発表を確認して追加してください。銀行休業日から入管や官公庁の閉庁日を推定しないでください。

## 公開データの更新
「JSONを書き出す」で作るファイルは、公開してよい為替・数字・休日だけです。個人の期限・元の宝くじ履歴・スプレッドシートIDは含みません。
全利用者に反映するには、アプリの公開先のdaily.jsonを差し替える必要があります。手動試験では、ダウンロードしたファイルをCodexに渡して反映を依頼してください。GASでの出力だけではサンプルURLは更新されません。

## 任意：Webアプリ配信（まだ必須ではありません）
GASにdoGetを用意しています。「デプロイ → 新しいデプロイ → ウェブアプリ」でJSONを返せます。実行ユーザーは自分。公開するならアクセス対象を公開してよい範囲に設定します。組織の制限で匿名公開できないこともあります。
ブラウザからの直接接続はGoogleの認証・リダイレクト・CORSを実機で確認する必要があります。本セットでは直接接続せず、JSONファイルによる手動運用を採用しています。
Webアプリから返るのは最後に手動出力した値です。公開URLから更新処理は呼べません。

## 自動化は完成後
installNoonExportTriggerは将来用です。今は実行しません。実行するとタイ時間の12:00前後でシート内容を書き出します。厳密な12:00実行は保証されません。為替の収集・宝くじ分析・公開先へのアップロードは行いません。

## 確認項目
- 為替を変更→JSON出力→アプリへ読み込み→換算結果が変わる
- ラッキーナンバー07の先頭0が保持される
- Bangkokの10/16休日がバンコク選択時だけ出る
- 不正なレート・日付・重複数字は出力前に停止する
- エラー時は前回の出力JSONを残す
- PM2.5・天気はスマホで通信して取得。GASやシートには入れない
